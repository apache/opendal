# Backblaze B2 S3-Compatible API

Enable `services-b2-s3` to use `b2-s3://bucket/prefix`. The URI authority
is the bucket name. Set `region` to the region shown in the bucket's S3
endpoint. OpenDAL uses it to sign requests and derives
`https://s3.<region>.backblazeb2.com`. Set `endpoint` to override the base
URL. Requests use path-style addressing by default. Set
`enable_virtual_host_style=true` to put the bucket in the hostname.

Use a Backblaze application key's `keyID` and `applicationKey` as
`access_key_id` and `secret_access_key`. The S3 API rejects the master
application key. The `b2` scheme selects the B2 Native API.

See the [S3 API introduction](https://www.backblaze.com/apidocs/introduction-to-the-s3-compatible-api),
[request URLs](https://www.backblaze.com/docs/cloud-storage-call-the-s3-compatible-api),
and [AWS SDK example](https://www.backblaze.com/docs/cloud-storage-use-the-aws-sdk-for-javascript-v3-with-backblaze-b2).

## Example

```rust
# fn main() -> opendal_core::Result<()> {
use opendal_core::Operator;
use opendal_service_s3::B2S3;

let op = Operator::new(
    B2S3::default()
        .bucket("example-bucket")
        .root("prefix")
        .region("us-west-004")
        .access_key_id("example-access-key")
        .secret_access_key("example-secret-key"),
)?;
# Ok(())
# }
```
