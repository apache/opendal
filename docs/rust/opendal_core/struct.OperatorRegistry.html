Expand description

Registry of service, context, and layer factories for string-based operator configuration.

Operator::from_uri and Operator::via_iter use the global registry returned by OperatorRegistry::get. Use OperatorRegistry::load to construct a service with its configured base context and ordered layers. Replacing a factory changes subsequent lookups. Operators already loaded keep their service, base context, and layers.

pub fn get() -> &'static Self

Get the process-wide registry used for string-based operator construction.

The memory service is always registered. Other schemes, context providers, and layers must be registered before use. The opendal facade installs the factories it provides for enabled Cargo features when it initializes its defaults. With split crates, use the component’s registration function or register a factory directly.

pub fn register_context<F>(&self, name: &str, factory: F)
where F: Fn(OperationContext, HashMap<String, String>) -> Result<OperationContext> + Send + Sync + 'static,

Register a context factory for context.<name>.* options.

Use a nonempty name containing only ASCII letters or digits, underscores, or hyphens. Names are matched case-insensitively in ASCII. Registering the same name replaces its factory for subsequent lookups. The factory receives the current base context and the options with context.<name>. removed from their keys. Return the input context unchanged when no options are recognized.

pub fn load(&self, uri: impl IntoOperatorUri) -> Result<Operator>

Load an Operator from trusted URI and key-value configuration.

The registry partitions the normalized options, then builds the service selected by the URI scheme from the URI components and unscoped options. It starts with the default OperationContext and invokes context factories with context.<name>.<field> options in ascending order of their normalized names. Each factory receives the previous context and the normalized field keys without their scope prefix.

The layers option lists layers from inner to outer, just like chained Operator::layer calls. For example, layers=timeout,retry places retry outside timeout and both outside the default layers that Operator::new applies. A missing, empty, or ASCII-whitespace-only list adds no configured layers. The registry trims ASCII whitespace around each comma-separated name and matches names case-insensitively in ASCII. It passes layer.<name>.<field> options to listed layers and ignores well-formed options for layers outside the list.

The layers wrap the service and the configured base context. Use Operator::with_context to replace that base context and replay the same layers. Factories can access the registry while running. Each lookup uses the registration in effect at the time of that lookup.

§Errors

Returns ErrorKind::ConfigInvalid for malformed scoped keys, even for inactive layers, and for invalid, empty, or duplicate names in a nonempty layer list. Scoped keys require a nonempty field and a name containing only ASCII letters or digits, underscores, or hyphens. Returns ErrorKind::Unsupported for an unregistered scheme, configured context, or listed layer. URI conversion and factory errors propagate to the caller.

Only pass URIs and options from trusted sources. URI query parameters can specify context and layers even when extra options are supplied. See the operator configuration specification.
