Builds a Cloudflare R2 service with provider-specific configuration.

§Configuration

Use crate::R2Config for serializable configuration or this builder for direct construction. The R2 preset accepts only R2 connection and credential settings. Use crate::S3 when an application needs the complete S3 configuration surface. Applications that use the opendal facade enable the services-r2 feature.

Set exactly one endpoint source:

  • Set account_id to derive https://<ACCOUNT_ID>.r2.cloudflarestorage.com.
  • Set account_id and jurisdiction to derive https://<ACCOUNT_ID>.<JURISDICTION>.r2.cloudflarestorage.com. Choose eu, fedramp, or us from Cloudflare’s available jurisdictions.
  • Set endpoint for a proxy, gateway, or test server. Omit account_id and jurisdiction when setting endpoint.

The preset uses auto as the signing region. It loads credentials from direct settings, standard AWS environment variables, or static credentials in the shared AWS credential files. It does not use AWS SSO, web identity, credential processes, ECS, EC2 metadata, or AssumeRole.

§Examples

Build an operator for a bucket in the us jurisdiction:

use opendal_core::{Operator, Result};
use opendal_service_s3::R2;

fn build() -> Result<Operator> {
    Operator::new(
        R2::default()
            .bucket("data")
            .account_id("example-account")
            .jurisdiction("us")
            .access_key_id("example-access-key")
            .secret_access_key("example-secret-key"),
    )
}

After registering the service, construct it from an r2:// URI:

use opendal_core::{Operator, OperatorRegistry, Result};
use opendal_service_s3::register_r2_service;

fn build() -> Result<Operator> {
    register_r2_service(OperatorRegistry::get());
    Operator::from_uri((
        "r2://data/root",
        [("account_id", "example-account"), ("jurisdiction", "us")],
    ))
}
